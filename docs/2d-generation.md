# 二维生图与配对 · 1.22

2026-10-31 用户决定放弃三维模型，使用上一版优化的二维形象；后续图片生成也统一为二维插画。此方向覆盖角色、换装与小屋素材，不需要建模、骨骼、VRM/GLB 或三维纹理。

当前已经接好的真实制作入口是“从图片创建 → 用本机模型重绘2D插画”。它只连接用户选择的、已经启动的本机 ComfyUI 服务。程序与随包 Skill 的 `generate_local_image.py` 共用固定核心节点和二维画风要求，保留用户写下的重绘和负向描述。打开向导、选图和修改描述不会发起生成；只有用户点击制作且已勾选重绘才提交一次任务。直接导入满意原图不会被强制重绘。

正向要求是二维手绘插画、清楚线条、柔和绘色、好看的轮廓与统一配色，保留参考身份、眼色、花纹和配饰；负向避开三维渲染、CGI、塑料玩偶、低面数和写实摄影。任务报告的 `art_style: 2d_illustration` 记录此次请求的画风，不能代替成品视觉检查。模型仍可能偏离要求，须预览后才创建角色。

猫与人物是一一对应的同一身份：可爱圆润的小猫与漂亮自然的成年人物共享眼色、毛色/发色和标志配饰。两张图片分别检查，不借用其它角色的人物图。换形态继续使用同一角色的聊天和记忆。

后续服饰与小屋生成沿用这些要求：

- 换装：以当前角色的二维原画为参考，固定脸、毛色/发色、眼色和姿态，生成同主题的猫款与成年人物款，分开保存和验收；缺少一款应明确标出。
- 房屋、树和家具：二维插画、统一视角和光影，按独立透明物件制作，置于猫身后的小场景；保留宠物、气泡和按钮的空间。
- 动作：先确认静态图，再为新图标定眨眼、呼吸和点击动作。新装没有匹配动作时用静态回退，不能直接套用旧图坐标后宣称已完成。

衣柜、小屋的生成授权页面目前仍是设计原型，没有真实生成适配器；不能把演示候选称为生成结果。没有新增云服务、自动付费或读取其它客户端凭据。历史 Grok 三维视频请求保留作制作记录，提交入口已禁用，未转成新的二维请求或自动重试。
