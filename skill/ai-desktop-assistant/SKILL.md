# AI 桌面助手工坊

把用户选择的角色做成可运行的桌面助手。Skill 负责组织制作、接入、验证和交付；透明窗口、动作、聊天与记忆由独立程序实现。交付一个 Skill 文件夹不等于桌面程序已经运行。

## 统一采用 2D 插画

用户已选择以 2D 助手作为默认制作路线：优先保留满意的插画，按需用本机模型生成或重绘、去背景，再制作可导入角色与小幅二维动作。不要为了提供动画先重建三维模型。新图先做静态预览，再标定眼睛、头部和身体，检查眨眼、呼吸、摸头与戳戳的关键帧后才制作完整动作。现有坐标不能直接套到新图；一张图不能保证自动生成大幅动作或被遮挡的部位。

用户于 2026-10-31 取消三维模型路线；当前程序制作、换装和小屋素材统一采用二维插画，不再提供三维生成或模型选择。保留已有图片、预渲染动画与原始设计历史，不替用户删除素材。二维角色仍可使用聊天、记忆和任务提醒，当前流程不需要 Blender 或三维运行库。

## 从现有成果继续

先确定当前工作区里的程序、角色素材和已有配置，保留用户的聊天记录、记忆、外观和模型选择。本机现有星伴源码通常位于 `<助手源码目录>`；安装记录位于 `%LOCALAPPDATA%/SATLOOT/StarPet/installation.json`，只取程序路径，不输出同目录的运行令牌或聊天内容。跨机器以实际工作区和安装记录为准，不把本机路径写成必要条件。

用户只要求打开、关闭或换图时，完成该项操作，不重新制作整套应用。已有 `satloot-agent-pet` 是兼容操作入口，可以继续保留；新的制作工作统一在这里组织。

按实际任务选择引用：

- **制作猫与一一对应的人物形态**：读 [配对角色](references/paired-roles.md)，使用程序的“创建猫 + 对应人物”或 `build_pairpack.py`，两种形态共用同一角色和记忆。

- **从一张图开始做完整助手**：先读 [完整制作入口](references/quickstart.md)，使用 `create_assistant.py` 串联形象和角色包。
- **在程序里选图、重绘、去背景和确认创建**：读 [图形制作向导](references/image-workshop.md)，使用“角色 → 从图片创建”。
- **制作或改进助手、连接模型、联动客户端**：读 [程序架构与连接](references/architecture.md)。
- **整理聊天记忆、确认保存或排查旧记忆丢失**：读 [记忆整理与保存](references/memory.md)。
- **查找设置、检测连接或确认修改是否生效**：读 [设置与连接草稿](references/settings.md)。
- **用已有 Qwen3-4B 权重在本机聊天**：读 [本机聊天引擎](references/local-chat.md)，使用配套服务脚本；不需要 Ollama 程序。
- **使用自己的图片、生成形象、导入角色或升级动画**：读 [角色制作流程](references/character-pipeline.md)。
- **选定原画后制作本地连续动作**：读 [本地动画制作](references/local-animation.md)，先检查关键帧，再使用源码中的可重建示例。
- **使用本机已验证的 SDXL 生图环境**：读 [本机生图引擎](references/local-image.md)，按实际安装管理后台服务。
- **验证、打包、升级或交付**：读 [验收与交付](references/verification-delivery.md)。

## 可执行的本机探测

需要本机聊天或生图时先运行：

```powershell
python "<skill>/scripts/probe_local_runtime.py" --output "<工作区>/local-runtime.json"
```

非默认端口可加 `--ollama-url http://127.0.0.1:端口` 或 `--comfy-url http://127.0.0.1:端口`。脚本只访问回环地址，读取 Ollama 模型列表和 ComfyUI 系统摘要，并检查已知 Codex 安装位置；不启动服务、不安装依赖、不下载模型、不读取认证、不调用推理。运行前不需要为了探测关闭正在工作的客户端。

结果区分“服务未连接”“接口结构不匹配”“发现服务但没有模型”和“发现程序但尚未验证登录”。Ollama 的云模型条目单独标记；本机端口并不自动证明模型在本机计算。缺少服务时继续完成独立的角色、界面和打包工作，准确列出仍缺的引擎或模型，不替用户改成别的云服务。

已有常见格式图片时，优先使用统一制作入口（技能修订1.13.1支持PNG/JPEG/WebP/BMP/TIFF/GIF，动态或多页只取第一帧），生成独立制作目录、角色包、说明和阶段报告：

```powershell
python "<skill>/scripts/create_assistant.py" --app-source "<助手源码目录>" --image "<角色.png>" --name "我的助手" --output-dir "<工作区>/我的助手"
```

只有显式指定 `--generate` 并提供本机服务、模型名和提示词才会先重绘。需要透明图时再加 `--remove-background --background-model <已校验的u2netp.onnx>`。它复用角色包、本地生图与本地去背景工具，不安装依赖、不下载模型、不启动服务、不自动切换正式角色。阶段失败就停止；不能把“图生成了”当成“助手已经装好”。完整参数和后续聊天验证见完整制作入口。

只需要一个角色包文件时，也可用配套命令生成并重新导入验证：

```powershell
python "<skill>/scripts/build_rolepack.py" --app-source "<星伴源码目录>" --image "<角色.png>" --name "我的助手" --output "<工作区>/我的助手.zip"
```

可加 `--persona "角色设定"` 和 `--personality gentle|playful|concise`，明确选择温柔、俏皮或简洁风格。构建使用应用自身的角色包库，自动建立独立临时状态并清理，只交付指定的新 ZIP，不改原图、不选择正式角色、不触碰生产记忆。未找到源码或 PySide6 时明确报错，不偷偷下载依赖。

已有本地 ComfyUI 和兼容 checkpoint 时，可调用 `scripts/generate_local_image.py` 从自定义 PNG 重绘形象，再交给角色包工具；完整命令、输入限制和实际验证范围见角色制作流程。它不自动下载权重，不保证透明背景，也不产生三维骨骼。

已有完整 Qwen3-4B safetensors 和 PyTorch/Transformers 环境时，可调用 `scripts/run_local_chat.py` 启动只绑定回环地址的文字聊天服务。该服务兼容应用使用的 Ollama 两个接口，实际引擎为 Transformers/PyTorch。首次请求加载模型，默认空闲十分钟退出；不会下载文件、读取云端凭据或改变正式模型选择。当前已实际验证自定义图片角色、本机显卡回复、重载后读取长期记忆及角色记忆隔离；ComfyUI 与 SDXL 的一次真实重绘也已完成，透明背景与动画另行检查。

## 必须保留的产品约定

- 角色外形、说话设定、聊天记忆和真实任务状态分别管理。摸摸、闲时动作和聊天回复不能改写工作任务，也不能遮住等待确认、错误或刚完成的真实提示。
- 模型连接沿用用户已经选定的方式。Codex 现有登录交给官方程序处理；本机模型使用用户明确选择的已有模型。不要复制其他客户端的凭据、把凭据交给反代服务，或用新供应商覆盖已取消的选择。
- 图片、连续动画、Live2D 和 3D 模型分别说明。导入图片即可做静态助手；不能称为自动完成了骨骼、口型或三维动画。
- 聊天记忆可查看、编辑、删除，独立于任务日志。切换角色不得静默清空记忆；导出角色或打包程序不携带真实对话、登录资料、运行令牌或测试存档。
- 开发验证使用新建的测试目录，默认后台、静音、不抢焦点、不切换桌面、不发送系统输入。隔离图形环境失败就停止图形测试，不回退到用户桌面测试。
- 用户要求制作时持续完成可执行程序和必要验证；用户仅要求研究时不安装、启动或改真实配置。已获授权的常规可逆操作不重复索取确认，新增付费服务、下载大型模型等超出原范围的承诺另行明确。

最终交付说明实际形态、模型来源、哪些验证来自真实模型、哪些只是测试替身、程序是否已启动，以及可用的程序包和 Skill 包。按实际运行结果报告，不把待实现能力写成已经具备。
