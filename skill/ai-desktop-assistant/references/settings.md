# 设置与连接草稿

AI桌面助手 1.9.0 的详细设置分六类，顶部切换分类，底部保存状态与“保存全部设置”始终可达。分类切换只切换显示，不调用模型、不落盘，保留各组滚动位置与本次草稿。

| 分类 | 内容 |
| --- | --- |
| 角色与称呼 | 名字、用户称呼、说话风格、人设、团团形态及角色页入口 |
| 聊天连接 | Codex、本机模型或 WorkBuddy／CodeBuddy；程序路径、模型、连接检测与官方登录 |
| 工作客户端 | 各客户端任务状态、完成提醒和 WorkBuddy Hook 接入 |
| 聊天与记忆 | 历史轮数、回复长度、等待时间、保存与记忆开关、工作状态计数 |
| 外观与提醒 | 大小、置顶、减少动态和静音完成提示 |
| 动作与陪伴 | 活跃度、点击互动、气泡、闲时短句、本机主动陪伴及临时安静 |

## 检测和登录不等于保存

“检测连接”使用当前草稿的接入方式、模型名、官方程序路径和本机地址，其他字段沿用已保存配置。它不提交人设、记忆或外观改动；即使人设草稿超过长度限制，也可以单独检测连接。成功返回的模型列表只填当前草稿，保存后才用于新的聊天。找到了程序或模型不代表已经验证真实回复。

检测期间如果换了接入方式、模型、地址、程序路径或角色，旧结果不能覆盖新草稿。取消后的迟到结果也不能重新写入。正常聊天、记忆候选整理仍使用已保存的连接，而不是尚未保存的设置页内容。

“官方账号登录”仅适用于 WorkBuddy／CodeBuddy，按连接草稿打开官方窗口，由官方程序处理认证。它不自动保存设置或切换当前聊天接入；完成登录后保存连接，再发送一条消息验证。此按钮由用户主动点击，会打开可见登录窗口，不能在后台验收中替用户触发。

启动已登记的本机模型只填写连接草稿，仍需保存后切换。任务 Hook 的“接入／修复”、临时安静和“保存并试一句”是明确的立即操作，按各按钮说明处理；不要把全部按钮都解释成只改草稿。

## 保存与失败恢复

修改后显示“有未保存的修改”。保存全部设置提交六组草稿；分类切换不会丢掉它们。当前窗口隐藏后重新打开或切换角色，会重新加载已保存设置，因此重要修改应先保存。不要把窗口内草稿称为可跨重启恢复的存档。

角色/聊天配置与外观/任务偏好分别保存。若第一份成功而第二份失败，界面明确报告已保存范围，旧外观/提醒偏好保持，草稿保留供重试；不承诺跨两个文件的完整事务。偏好文件自身先原子保存，成功后更新内存，失败修改不会在后续操作中被夹带写入。

验收使用隔离状态：检测成功/失败/取消和登录替身均不得改真实设置；分类跳转与草稿变化不落盘；明确保存后重新加载一致；失败后旧偏好保留、范围提示可见。另检查小窗口与双倍缩放下各分类无横向滚动，保存按钮与状态栏不被内容遮挡。真实账号登录仍需独立证据，不以替身验证代替。
