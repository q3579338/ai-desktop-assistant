# 记忆整理与保存

本页适用于带记忆候选功能的 AI桌面助手 1.8.0 及以后版本；先核实实际程序。Skill 组织操作，程序负责窗口和存储，模型只提出候选。它不是向量数据库，也不会自行阅读 Codex／WorkBuddy 的外部聊天。

## 用户操作

在当前角色的“记忆”页打开“从最近聊天整理记忆”，选择最近 1～24 轮，默认 8。点击“整理候选”才请求当前已保存的模型连接；未保存的设置草稿不生效。本机模型需已经启动；Codex／WorkBuddy 走已经选择的官方连接并使用其账号额度，找不到服务或未登录时显示实际错误，不自动切换供应商。

发给模型的材料只有所选范围内当前角色的用户发言，最多 8000 字，优先保留较新的完整发言；不截断句子，也不从范围之外补旧话。空白、明显凭据或无法容纳的发言会略过；凭据检查不是完备的敏感信息识别。不会附带助手回复、已有事实、任务内容、输入框草稿或其他角色记忆。关闭历史保存时，本次窗口里尚未保存的用户发言仍可明确选来整理。

结果最多 8 条，每条显示完整候选和对应原话。默认全部不勾选；用户逐条核对，必要时编辑，明确“确认保存所选”后才入库。程序校验来源编号和逐字连续引用，但不能仅凭引用证明候选含义正确；模型也可能漏掉其他偏好。不要宣称自动理解了用户的全部习惯。

停止或关闭不保存候选。生成后如角色、保存的连接设置、聊天或事实变化，旧候选失效，需要重新整理。结果本身不作为助手聊天回复存入历史，也不显示为任务完成。成功保存后仍可在记忆页查看、编辑和逐条删除。

## 存储边界

每个角色最多 50 条长期记忆，满额明确拒绝新条目，不自动挤掉最早内容。`add_facts` 接收最多 8 条，完整校验、精确去重和容量检查后一次原子写入；重复条目不占新位置。新增、编辑、删除或清空失败时，原内存状态和文件保持，候选修改可重试。备份与导出不能把真实记忆混进角色包、源码或程序包。

聊天显示历史与持久化历史分别维护。保存失败时已收到的回复可留在当前窗口，但持久化历史不变；下一次成功请求只保存当前新回复，不补存之前失败或关闭保存期间的内容。清空历史不删除长期记忆。关闭“回复时带上长期记忆”只影响后续聊天上下文，不删除文件。

## 验证

使用新建虚构角色状态。按 [验收与交付](verification-delivery.md) 检查未勾选不落盘、只保存所选修改、引用错配整批拒绝、取消与关闭丢弃迟到回复、换角色或设置后作废、满额和磁盘失败不损坏旧档，以及关闭历史保存后不补存。

需要真实模型验收时，用虚构明确偏好生成候选，人工核对所选候选确实被原话支持，记录实际选中了哪一条，不要求模型必须返回所有偏好。确认后重新创建存储对象、关闭最近历史上下文，再询问对应偏好；这是本次模型与存储链路验收，不是所有模型长期记忆质量的保证。界面替身测试与真实请求分别记录；换角色隔离可以先通过实际请求内容验证，无需为每个边界重复消耗推理。
