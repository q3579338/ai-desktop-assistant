# 在程序里从图片创建助手

1.10.0 的“角色 → 从图片创建”已接入完整制作向导。可先使用原图，也可明确选用已安装的本机 ComfyUI 重绘、U2NetP 去背景。向导打开、选图和修改文字均不会自动调用模型。

## 操作顺序

1. 选择 PNG、JPG/JPEG、WebP、BMP、TIF/TIFF 或 GIF，填写名字、人设和说话风格。默认制作2D助手。非PNG会保留原文件副本与摘要，另生成内部PNG；JPEG按照片方向显示，透明WebP保留alpha。动态/多页图片只取第一帧制作形象，完整原文件保留，不把这一帧宣称为已导入全部动画。最多32MB、边长4096。技能修订1.13.1的create_assistant.py与build_rolepack.py也支持这些格式，底层生图适配器仍只收符合模型尺寸要求的PNG。
2. 需要重绘时勾选“用本机模型重绘2D插画”，填已启动的 ComfyUI 回环地址，点击检查读取模型列表，选择实际 checkpoint 并描述改动。共享生图工具自动补充二维手绘、保留身份与完整轮廓的要求，并避免三维渲染/塑料玩偶风格；仍须人工检查最终画风和角色一致性。重绘使用固定核心节点；不接受角色包里的任意工作流或插件。
3. 需要去背景时勾选去背景，选择已有 Python 和已核验的 U2NetP 模型。Python 需要 Pillow、NumPy、ONNX Runtime；程序用隐藏的独立子进程调用固定工具，不下载模型或安装依赖。
4. 点击“制作预览”，等到结果出现，检查脸、手、耳朵、头发和透明边缘。原图已有透明通道也会保留；自动去背景不保证每一处细节都正确。
5. 确认后点击“创建角色”。程序生成角色包并在独立库重新导入验证，随后加入正式角色列表。再点“使用选中角色”启用。聊天连接和记忆设置仍由详细设置管理。

生图、去背景、聊天是三个独立环节。普通 PNG 创建无需生图模型；只有选择本机聊天模型时，后续聊天才在该服务处理。向导只连接已经启动的生图服务，不负责安装或启动 ComfyUI。现有机器的安装和后台启动方式见 [本机生图](local-image.md)，换机重新核对环境。

## 结果在哪里，失败如何继续

每次制作保存在助手状态目录的 `creations/creation-<随机值>/`，含原图副本、已完成的图片、阶段记录和 `creation.json`。个人状态目录通常是 `%LOCALAPPDATA%/SATLOOT/StarPet`；测试须另用独立状态目录。角色创建后目录里另有 `.aipet`，可交付角色包；报告可能含本机路径和提示词，不随公共程序发布。

“读取已有制作报告”仅接受向导自己的 `creation.json`。读取会重新校验目录归属、PNG、文件摘要、工具记录；未完成、被修改或缺失的文件不能假报成功。Skill 命令行入口的 `result.json` 格式不同，应按 [完整制作入口](quickstart.md) 的恢复方式处理。

若退出程序使报告停在“处理中”，读取时只复制报告已记录且重新核验通过的图片，建立新的中断恢复目录；原目录保持不变。恢复结果显示为部分完成，需再次明确确认，不扫描或猜测尚未记入报告的文件，也不重新提交模型任务。若原任务仍在运行，它仍可在原目录完成。

失败或取消后若已有经过核验的图片，显示“上一步已完成的图片”。用户可以明确点“用当前结果创建角色”，或点“从已有结果继续”处理。继续会创建新目录并保留来源记录，自动关闭重绘，不重新提交原来的生图任务。需要全新重绘时重新选择原图并明确发起新制作。

“停止”或关闭窗口会取消本次等待，不导入迟到的角色包。已提交到 ComfyUI 的任务可能继续，程序不会中断其他人的队列；不要将取消等待理解为服务任务已撤回。已经完成的文件保留。关闭程序会停止它自己启动的去背景进程。

## 交付与验证

最终程序包需要完整 `_internal/creation-tools/` 中的三个固定脚本，与对应 Skill 来源逐字节一致；不把用户自选脚本当作制作工具。程序界面静态创建无需另带源码或 PySide6；Skill 的命令行制作入口仍需要对应源码和 Python 依赖。

验证至少覆盖原图→预览→明确创建、不自动切角色、停止/关闭后迟到结果不导入、失败候选继续制作、小窗口和缩放、打包程序工具加载。真实本机模型验证与 HTTP/进程替身测试分别报告；不能把 PNG 角色包称为完整 Live2D 或 3D 模型。
