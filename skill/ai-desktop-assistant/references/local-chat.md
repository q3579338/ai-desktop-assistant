# 已有 Qwen3-4B 的本机聊天

`scripts/run_local_chat.py` 提供可以直接运行的本机文字服务。它加载用户已有的 Qwen3-4B safetensors，不下载模型，不用云端账号，也不在程序发布包里附带约 8 GB 权重。实际引擎是 Transformers 与 PyTorch；它只实现助手需要的 Ollama 兼容 `GET /api/tags`、`POST /api/chat`，并非 Ollama 程序。

## 前提与启动

确认模型来自 [Qwen 官方仓库](https://huggingface.co/Qwen/Qwen3-4B)或 [Qwen 魔搭仓库](https://modelscope.cn/models/Qwen/Qwen3-4B)，保留原许可证并逐文件核对该来源公布的摘要。只允许 Qwen3-4B 的本地配置、分片 safetensors 索引及 tokenizer，不加载仓库 Python 代码。当前配置检查不代替权重摘要与来源校验。

本次验证环境为 Windows、RTX 4090、Python 3.13、PyTorch 2.14.0+cu130、Transformers 5.21.0、tokenizers 0.23.1、safetensors 0.8.0。CUDA 使用 BF16；CPU 选项会使用 FP32，内存需求更大且本次未做速度验收。不要承诺任意显卡或低内存机器都能运行；先检查环境和可用资源。

```powershell
python -I -B "<skill>/scripts/run_local_chat.py" --model-dir "<本机Qwen3-4B文件夹>" --dependency-dir "<可选的独立Python依赖文件夹>" --port 11536 --idle-seconds 600
```

若依赖已在该 Python 的标准安装目录中，省略 `--dependency-dir`。依赖目录是用户或本次工作明确选定的本机库目录，不接受角色包指定的代码目录。默认用 CUDA；显卡不可用时返回错误，不静默转成云推理或占满 CPU。

后台启动应使用宿主允许的无窗口进程；Windows 的 `subprocess.Popen` 使用 `CREATE_NO_WINDOW`，PowerShell 的 `Start-Process` 使用 `-WindowStyle Hidden`。保留自己创建的进程句柄，需要停止时只停止这一进程，不按名称结束所有 Python。不要修改系统 PATH、开机启动或用户全局 Python。测试结束关闭本次服务，正式服务默认在最后一次推理结束后空闲十分钟退出，释放显存；需要再次聊天时重新启动。

服务启动输出 `ready` 只表示本地接口可用；`/health` 的 `loaded` 才说明已加载模型，实际回复成功才是推理验证。脚本不写聊天日志。第一次请求包括模型加载，之后的短回复通常更快，但应报告本机实测而不是固定性能承诺。

## 在桌面助手中连接

1.4.0 已提供手动启动、检查状态和停止按钮。为已明确安装的引擎登记 `<应用状态目录>/local-model-runtime.json`，只保存以下路径；先检查实际文件与来源，不能从角色包取得这些执行路径。没有安装说明时按钮提示未安装，不会下载。升级不能改掉用户已有同名安装说明；先核对、备份后按已授权范围更新。

```json
{
  "schema": 1,
  "python": "<本机Python绝对路径>",
  "script": "<本技能scripts/run_local_chat.py绝对路径>",
  "modelDir": "<Qwen3-4B绝对路径>",
  "dependencyDir": "<独立依赖绝对路径>",
  "url": "http://127.0.0.1:11536"
}
```

点击启动仅填入连接草稿，明确保存后才切换；脚本和路径不随角色包导出。按钮启动的进程由当前助手实例持有，停止或退出只结束它自己的进程。换电脑的普通程序包不附此机器说明和大模型权重。

1. 在详细设置的连接方式中选择“本机模型 · Ollama 兼容接口”。旧版 1.3.0 显示“本地 Ollama · 离线模型”，也可使用同一兼容接口。
2. 地址填写 `http://127.0.0.1:11536`，检测连接并选择 `qwen3-4b-local`。
3. 保存后发送一条测试消息。先在隔离测试身份完成验证；正式切换只在用户已经选择本机模型时进行，保留原 Codex/WorkBuddy 配置。

探测命令可用：

```powershell
python "<skill>/scripts/probe_local_runtime.py" --ollama-url http://127.0.0.1:11536 --output "<工作区>/local-runtime.json"
```

接口名称不改变真实计算来源。默认仅监听 127.0.0.1，拒绝浏览器 Origin 和不匹配 Host，不提供跨域、工具调用、图片上传、文件读取或模型拉取接口。并行请求限制为四个连接、一次推理，正在回复时新推理返回忙碌。请求有大小和格式上限。

推理设置为本地文件加载、关闭遥测、明确禁用隐式 token，进程审计钩子拒绝 Python 出站连接。不会读其他客户端的认证或聊天。用户输入仅在本机进程内参与推理；本机其他同用户进程的访问边界仍取决于操作系统，不能把回环服务宣传为用户级身份认证。

当前为非流式回复，最多 1024 新 token、输入加输出最多 8192 token。关闭思考模式，按照官方非思考建议使用温度 0.7、top_p 0.8、top_k 20。客户端断开或推理超时后在生成检查点停止，不将半截文字标成成功；首次模型加载期间取消需等加载返回，不能承诺瞬时释放资源。

## 已验证与未验证

2026-10-28 在独立测试目录完成真实 GPU 请求，所有内容都是虚构测试人物：

- 原创机器人图片导入为新的自定义助手，导出并重新导入角色包，原图摘要不变。
- 保存“青团、茉莉花茶”两项虚构信息，实际模型正确回答。
- 禁用最近聊天上下文，重新创建 ChatStore 后，实际模型仍从该角色长期记忆回答“茉莉花茶”。这是应用存储重新加载，不是整个系统重启。
- 切换到另一角色后，模型回答不知道喜欢什么茶，没有带出前一角色的记忆；切回后原记录仍在。
- 测试服务结束后已关闭。正式聊天、记忆、模型选择未读取或改写。

这些证明本机文字推理与图片角色/记忆能串联，不证明图像生成已运行。ComfyUI 重绘、自动透明背景、自动骨骼、Live2D、语音及实时 3D 必须按各自实际实现和测试单独报告。

## 主动陪伴与上下文说明（1.5.0）

普通聊天显示实际随请求发送的长期记忆条数和历史轮数；成功后保存当次摘要。不要把这理解为模型已正确记住或引用了全部资料。取消、失败与旧历史不补造成功摘要；“记住”本机命令仍单独标识。

“偶尔主动聊一句”默认关闭，只使用本机模型。间隔 5～60 分钟；保存并试一句是手动预览，不需要打开自动开关。不会启动模型服务，不会把本机不可用改成云账号调用。

主动请求没有聊天历史和任务信息。仅当通用记忆和陪伴记忆两个开关都开启时，附带当前角色保存的明确事实。生成结果不自动持久化为聊天或记忆，避免模型自己的话变成用户事实。换角色、改连接或开始聊天时，旧请求取消；迟到结果不能显示成新角色的话。

工作、确认、错误、完成通知、隐藏、安静和减少动态都优先。解除后重新等待一个完整间隔，不追补错过的请求。请求超时、服务不可用或回复不符合短句限制时，保留正常提示并等下一间隔。短句最长 28 字符、显示约 14 秒；明确的任务成功、屏幕观察或作息猜测会被有限规则拒绝，但这不是完整事实验证器。
