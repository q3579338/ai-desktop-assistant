# 程序架构与连接

## 沿用现有星伴工程

星伴使用 Python/PySide6 原生透明窗口。先阅读当前项目的入口、设置、角色加载和模型适配器，不仅凭本文推断新版本字段。本机源码基线中这些职责分别在 `main.py`、`starpet/storage.py`、`starpet/gui.py`、`starpet/characters.py`、`starpet/behavior.py`、`starpet/companion.py` 与 `starpet/chat_gui.py`。

分开保持这些职责：

| 层 | 负责什么 | 不应混入什么 |
| --- | --- | --- |
| 角色和动作 | 图片、已验证的动画、点击反馈、形态切换、活跃度 | 模型凭据、聊天记录、真实任务修改 |
| 独立助手 | 用户主动聊天、角色设定、上下文、可编辑记忆 | 未经选择的外部聊天全文、代替用户批准任务 |
| 状态适配 | 接收 Codex/WorkBuddy 元数据、真实等待与完成、去重 | 假完成、把工具结束当整轮完成 |
| 本机存储 | 设置、助手自己的记忆、完成记录，分别保存 | 可发布包中的个人数据 |
| Skill | 识别任务、调用实际工具、验证、打包与说明 | 冒充常驻进程或模型 |

现有设置采用独立 JSON 文件；更新增加带默认值的新字段，读取旧配置保持兼容，写入用临时文件后原子替换。角色包与用户数据分离；换图只改外观，切换角色转到该角色自己的聊天和记忆，原角色记录保留。团团继续使用原来的 `companion-memory.json`，其余已验证的角色 ID 使用 `role-memory/<角色ID>.json`；`role-profiles.json` 保留用户给每个角色修改的名字与人设。连接、称呼和通知等共享设置不随角色切换被覆盖。

角色切换通过 `ChatStore.switch_role()` 与控制器入口，不直接修改设置中的 `roleId`。聊天请求进行中先结束或取消，避免迟到回复写进新角色。跨设置文件写入失败时，当前角色、显示的聊天和实际记忆目标必须一致；不能只在屏幕留下旧角色、后台却已经换到另一份记忆。继续保留模型超时、取消、失败重试及清空记录后的迟到回复保护。

1.8.0 的候选整理分为 `memory_suggestions.py`（仅组织资料与校验引用）、`memory_gui.py`（非阻塞审阅窗口）和 `chat_gui.py`（当前连接请求、范围快照及确认）。候选不会自动入库；事务写入由 `ChatStore.add_facts()` 负责。容量已满与写入失败不丢旧记忆，历史保存失败或关闭保存期间的内容不在后来自动补存。完整操作和验收见 [记忆整理与保存](memory.md)。

模型选择按连接方式隔离：`modelsByProvider` 只含 `codex`、`ollama`、`codebuddy` 三键，兼容字段 `model` 对应当前接入方式。旧设置只迁入其原 provider，读取不落盘；界面切换时保存各自草稿，不能把本地模型名传给另一个官方 CLI。角色切换仍共用整组连接设置。

1.9.0 的 `settings_gui.py` 只负责分类、滚动和固定保存栏，不持久化任何配置。连接检测与官方登录使用独立草稿快照，不调用整页保存；正常聊天仍用已保存配置。外观偏好只在原子写入成功后更新原内存映射。两份设置部分写入失败时必须如实反馈已保存范围，不能宣称整页成功；详见 [设置与连接草稿](settings.md)。

本机专注计时使用独立 `focus-timer.json`，由 `FocusTimer` 负责暂停、恢复、重启与一次提醒。到点只进入等待用户下一步的状态，不改任务 Core，不发模型请求；离线不自动循环。显示静音提醒前必须先持久化提醒 ID，真实任务、聊天和安静/隐藏优先。不要将“专注时间到了”表述成工作任务已完成。

## 本机聊天模型

执行 `scripts/probe_local_runtime.py`，从 Ollama 兼容接口返回的实际模型中选择。此脚本仅做 `GET /api/tags`，不会拉取模型、加载模型到显存或发送聊天。内置 `run_local_chat.py` 是 Transformers/PyTorch 引擎，参见 [本机聊天引擎](local-chat.md)；接口兼容不代表安装了 Ollama。

Ollama 服务在回环地址不代表其中所有模型都离线：模型项可能带 `remote_model` 或 `remote_host`，探测报告将这些条目标为 `cloud`；名字带 `cloud` 也保守标记为待确认的远程候选。要求本机计算时排除这些候选，进一步核对所选模型和工作流的运行方式。模型列表可达也不能证明该模型支持聊天、内存足够或推理成功，需另做真实的一轮聊天验证。

应用的本地连接仅接受 `http://127.0.0.1:端口`、`http://localhost:端口` 或 IPv6 回环地址。连接通过直接 HTTP 客户端，不使用系统代理，不跟随重定向；不要根据服务器返回的跳转地址发送对话。探测器也可读取有有效证书的本机 HTTPS 服务，但实际应用是否支持 HTTPS 以其适配器为准。

用户未安装本机模型时，不擅自拉取数 GB 的文件或占用显卡。先给出发现结果；若用户已授权安装指定模型，按其下载位置、容量和运行约束继续。既没有本机模型、又未选用云连接时，仍可交付离线外观、互动和设置，明确聊天尚未接通。

官方接口依据：[Ollama 模型列表](https://docs.ollama.com/api/tags)；远程模型字段见 [Ollama API 类型定义](https://github.com/ollama/ollama/blob/main/api/types.go) 中 `ListModelResponse`。接口变化时以用户安装版本和当前官方资料核验。

## Codex 现有登录

用户选择使用当前 Codex 账号时，由官方 Codex 程序管理认证。查找已知官方安装目录或用户明确提供的程序路径，核对实际版本支持的独立调用方式；不要读取、复制或输出 `auth.json`，也不修改用户的全局启动脚本。

当前工程采用独立、临时会话，将助手设定、启用的记忆及这里的对话通过标准输入发送。它不向用户已有聊天发消息，关闭执行工具、插件、Hook 和项目规则载入，避免“陪聊”意外变成执行任务。保留受控工作目录、只读限制、取消时只结束自己启动的进程。

该方式使用 Codex 账号额度，属于由官方服务处理的聊天；不能宣传为本地大模型。找到 `codex.exe` 只说明程序存在，登录状态、参数兼容和真实回复需分开验证。[Codex 非交互模式文档](https://learn.chatgpt.com/docs/non-interactive-mode) 可用于核对当前接口，应用源码中的实际参数和测试结果才是本次交付依据。

## WorkBuddy 与 Codex 的真实状态

WorkBuddy 账号聊天与下面的任务 Hook 分开。当前程序提供独立官方 CodeBuddy CLI 2.177.1 适配和用户点击的官方登录入口，使用自己的 `codebuddy-profile`／`codebuddy-runtime`，不复用桌面认证文件。探测只验证版本和参数；首次真实登录与回复成功才可声称接通。纯聊天参数禁用工具、MCP、Hook、父目录记忆与会话持久化，传给模型的资料来自这里的对话。未知 CLI 版本须重新核验，不自动放宽检查。本机实际账号回复尚未验收；当前证据为协议替身测试。详见应用 `docs/workbuddy-chat-findings.md`。

WorkBuddy 的生命周期 Hook 只传递来源、会话及事件类别等必要元数据。接入保留已有 Hook 和所有无关设置，新增/移除按本项目精确归属处理；不得把完整旧备份覆盖用户后续修改。

已审 2.177.1 的登录与聊天还共同关闭插件后台管理和已安装插件初始化：隐藏参数 `--no-plugin-management` 加 `CODEBUDDY_DISABLE_PLUGIN_INSTALLS=1`、`CODEBUDDY_PLUGIN_BACKGROUND_MANAGEMENT=0`。此项根据该版本公开代码核对，不能扩展到未知版本；不因参数隐藏而要求它出现在公开帮助里。专用目录已有插件或额外规则时保留并拒绝，不删除用户内容以绕过边界。

Codex 状态适配增量读取已经存在的会话日志；启动时从末尾建立游标，不重放旧庆祝，不把内部子任务算成用户的新任务。事件优先级保持等待、错误、工作等真实状态可见，本轮完成有独立通知通道；工具执行结束并不是整轮完成。未观察到审批事件时如实说明覆盖范围。

任务数据和聊天数据各自保存。用户启用“聊天时带上工作状态”时仅发送所列计数或明确选择的字段，不默默吸收其他客户端的对话全文。后台动作、临时安静和短句无需模型，不对这些本地反馈收取或宣称消耗模型推理。
