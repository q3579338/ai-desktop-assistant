# 验收与交付

## 检查分层，证据不混用

| 检查 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| `probe_local_runtime.py` | 本机接口结构与可达性、模型列表、已知 Codex 程序存在 | 真实聊天、生图、登录有效、资源足够 |
| 单元测试与模型替身 | 状态优先、取消、重试、记忆读写、输入限制和错误分支 | 真实模型推理与真实客户端事件 |
| 本地生图工具的回环 HTTP 替身 | 固定节点图、上传前模型校验、任务归属与 PNG 输出检查 | 实际 ComfyUI、显存足够、真实出图或角色一致性 |
| 本机聊天服务的回环 HTTP 替身 | 请求边界、忙碌、断连取消、连接上限、空闲退出 | CUDA 可用、权重可加载、模型回答质量 |
| `create_assistant.py` 的阶段测试 | 原图只读、静态或重绘分支、重新导入、失败停止与报告一致 | 没有真实 GPU 出图时不能证明生图效果 |
| Qt offscreen | 排版、状态渲染、控件流程、尺寸与缩放 | 用户桌面上的实际合成、鼠标穿透或多显示器手工体验 |
| 独立 Windows 测试桌面 | 原生窗口和渲染在隔离环境的表现 | 已在用户实际桌面完整人工验收 |
| 已选择模型的真实一轮请求 | 本次模型连接和回复成功 | 永久可用、所有模型行为或额度不受限 |
| 真实客户端自然事件 | 该客户端该事件路径实际到达 | 尚未出现过的全部审批或边缘事件 |

Skill 的实现检查（有相关代码变化或首次验证整个包时使用，不为文档修订重复所有模型替身测试）：

```powershell
python -B -m unittest discover -s "<skill>/tests" -v
```

这些测试使用本机临时 HTTP 服务、测试目录和模型替身，不需要真实模型、账号或外网；各测试自身仍需相应已安装的 Python 依赖。它们覆盖探测、生图协议、去背景边界、聊天服务和统一入口，并在存在相邻星伴源码时运行角色库集成。独立安装 Skill 且没有相邻源码时，相关源码集成测试会明确跳过，不能把跳过写成通过，也不能把替身成功写成真实推理。

测试目录必须位于 Skill 安装树和正式状态之外。可在测试进程环境设置 `STARPET_SKILL_TEST_TMPDIR`；部分测试与统一入口还使用 Python 系统临时目录，需要另将该进程的 `TEMP`、`TMP` 指向工作区内已存在的可写临时路径。保留测试实际通过、失败、跳过数量及依赖版本，不依赖只读 Skill 安装目录可写。

## 可移植制作验收

“本机做过一次”与“别处拿到包后可照说明制作”分别验收。变更文档或交付结构时先做低成本核对；没有实现变化就不重复完整推理或整套应用测试。

1. 解压最终 Skill 包到新的工作区路径，确认完整脚本、引用、元数据和测试可读取；检查内部相对链接，不依赖原工作区或用户目录中的遗漏文件。脚本的 `--help` 应可运行，不启动模型或服务。
2. 使用明确提供的可信助手源码和该 Python 的 PySide6，按 quickstart 跑一次静态 PNG→角色包。输入与输出放在 Skill 目录之外；用隔离临时角色库重新导入，核对名字、风格、原图摘要及来源标记。这个步骤才证明源码和角色打包依赖已经可用；仅有 EXE 不能替代 `--app-source`。
3. 若本次交付需要本地重绘，另核实实际服务地址、checkpoint 枚举、核心节点及权重来源；先确认静态打包能用，再执行一张已授权的真实生成。去背景与聊天各自按对应来源、摘要、依赖及真实请求验收，缺少哪项就明确列出，不能把旧机器的报告当新机器通过。
4. 检查输出 result.json 的状态、已完成阶段、原图未变、包和最终图片摘要；存在 `needs_visual_review` 时实际查看透明边缘。保留生成任务的确认状态，未知提交不得重试。报告失败或 cancelled 时，不因目录里出现 ZIP 就标记完成。
5. 仅在用户已要求启用时导入程序并保存连接；制作验证继续用隔离状态。换机安装说明中的执行路径和端口由新机器实际值建立，不附带旧机器的 local-model-runtime.json、凭据、记忆或运行令牌。

跨目录检查不能写成第二台实体电脑已通过；接口替身不能写成 GPU 推理已通过。完整角色动作另查实际帧、时长、透明度、状态映射与交互；静态角色包或单段 idle 通过不能覆盖其它动作。

## 应用验收

每次测试使用新的明确测试目录和身份，启动前确认它不是正式状态路径。示例问题、伪造记忆和任务事件不得进入真实用户槽；真实数据备份也不能混入发布包。修改旧版数据读取时，验证原始文件未被加载步骤重写，保留用户有效历史。

按本次改动检查相关部分：

- 自定义图和角色包：坏图/坏包拒绝后旧角色仍可用，导入只复制必要文件，保存后重启可恢复，切换不改记忆或模型。包中的绝对路径、路径穿越和任意脚本不能被当作资源执行。
- 桌宠互动：单击、双击、拖动、落地、动作冷却和安静模式有真实反馈；气泡隐藏后原区域不拦截点击；等待、错误、本轮完成优先。减少动态时不继续晃动，隐藏时不积压自动动作。
- 单次动作衔接：实际播放短片和超过原反馈时限的长片，观察全部帧与末帧停留，再返回待机；不能用跳到末帧代替完整播放。短句与动画分别结束，同种手势连点不重开，旧回调不能结束新动作；切换角色/形态、隐藏、减少动态和任务抢占后不补播旧片段。最终程序包也要覆盖至少一个正式片段的完整结束。
- 聊天和记忆：成功/失败/停止/重试清楚区分，失败不存成成功回复，迟到回复不恢复已清空记录。旧记忆加载、逐条编辑/删除、历史与记忆分开清空，关闭新记录保存不删除旧记录。切换角色后不带出前一角色的事实或历史，切回恢复原档与自定义人设；模拟写失败时显示角色与实际记忆目标仍一致。
- 主动陪伴：默认关闭且仅本机模型，无聊天历史、无任务正文、长期记忆双重开关；任务和主动聊天能取消后台请求，服务实际感知断开，迟到回复不能串入新角色；生成短句不进入用户记忆。真实模型品质与假引擎流程分别检查。
- 记忆候选：只选定范围用户发言、默认不勾选、原话可核对、编辑后明确保存；取消/关闭/范围变化丢弃旧候选。满 50 条或写入失败不挤旧记忆，不补存失败或关闭保存期间的聊天。真实模型可以略过偏好，验收记录实际选择的完整事实，不把必须提取某个主题当作通用要求；详见 [记忆整理与保存](memory.md)。
- 接入：真实任务状态有客户端来源，多会话不串线；完成通知不被另一个忙碌任务吞掉，不重放旧完成；原有 WorkBuddy 设置和 Hook 保留。
- 连接切换：各方式模型名独立，切换不沿用另一方模型，旧档读取不改写；聊天连接配置本身写入失败时保留原连接。官方独立 CLI 的发现不读取桌面凭据，找到程序不等于真实账号回复通过。
- 分类设置：切换不落盘、不丢本次草稿，各组滚动位置保留；固定保存栏可达。检测/官方登录只传连接草稿，不顺带保存其他字段；迟到结果不覆盖新草稿。外观偏好写失败保持内存与文件原值；跨配置文件部分失败准确报告范围，保留可重试草稿。见 [设置与连接草稿](settings.md)。
- 专注：暂停/恢复/退出重进、到点等用户继续、不补离线周期、提醒去重、写失败不假报成功；与真实任务状态分离，任务或安静/隐藏期间延后。受控时钟证明逻辑，不能写成真实等待多个长周期。
- 页面：小屏、常见尺寸和 DPI 下文字完整，长消息能滚动，主操作明确；模态窗口和滚动区不遮住保存、取消或错误提示。

所有图形测试后台、静音、不抢焦点、不切换桌面、不发送系统输入。可用时先用 Qt offscreen；需要原生检查时使用验证过的独立桌面工具，在创建 GUI 前校验测试桌面名。不得在隔离失败后回退到普通桌面。用户明确要求打开实际程序属于正常使用，不能把它混写成隔离验收。

## 打包与升级

图片向导还需检查原图和结果预览、处理失败后恢复、取消/关闭后迟到角色包不导入，以及固定制作工具在最终 EXE 中的加载。`creations/` 下的提示词、路径、输入图和报告属于用户制作资料，公共程序包与源码包不得携带。操作说明见 [图形制作向导](image-workshop.md)。

沿用项目构建脚本，保留许可证及素材来源。星伴 Windows 发布目录中 EXE 和 `_internal` 必须一起交付；只移动 EXE 不是可运行包。构建 PySide6 时保持已验证的系统库搜索路径，防止将 Node 等其他软件的同名 ICU 库混进程序。

更新到新版本前先在暂存目录构建和验证，不覆盖正在运行的 EXE。关闭时只操作自己启动或安装记录精确指向的星伴进程，保留可恢复的旧版本，再切换稳定路径；读取和保留原设置及记忆，不拿测试数据初始化正式槽。若真实用户设置在更新期间改变，重新读取后只合并本次必要项。

按用户要求分别交付下列成果，说明每个文件的用途与当前完成状态：

- **程序包**：可直接运行的完整目录压缩包、必要角色资源、版本与文件摘要；不含个人配置、聊天、认证、运行令牌、测试状态或证据目录。
- 专注事项名称与时间同样属于个人状态；升级保留 `focus-timer.json`，程序包、源码包与角色包不携带它。
- **Skill 包**：保留顶层 `ai-desktop-assistant/`，内含 SKILL.md、agents/openai.yaml、完整 references、全部 scripts 和对应 tests。当前可执行链包括 create_assistant.py、build_rolepack.py、probe_local_runtime.py、generate_local_image.py、remove_local_background.py、run_local_chat.py；不能只打包探测脚本。不要附带模型权重、虚拟环境、构建缓存或占位文件。
- **可用于制作的源码包**：用户需要在另一台电脑通过 Skill 继续制作时，同时提供对应版本的完整可信助手源码、依赖清单和许可证，或明确指向实际随交付提供的位置。源码包与运行程序包不是同一种文件；没有它时，应写明 CLI 打包尚缺 `--app-source`，不能称轻量 Skill 已独立包含整个运行环境。
- **角色包与制作记录**：经过重新导入的角色 ZIP，及本次原图/中间图摘要、阶段结果、处理来源与视觉限制。角色包只包含所需图像、动作和角色设定，不包含模型、执行路径或用户状态。需要继续制作时保留原图和源材料；对外共享原图与提示词遵从用户的范围，不把制作记录混入程序运行资源。

可移植交付清单应列出应用和 Skill 版本、程序/源码/角色/Skill 各包文件名与 SHA-256、所需 Python 依赖及已验证版本、模型来源和许可、哪些组件已附带及哪些需在目标机器准备。示例绝对路径只能标为原机器记录，实际命令应使用 `<skill>`、`<助手源码目录>` 等可替换路径。本机私有的服务控制器若未纳入交付，明确它不是目标机器必备脚本，并提供使用已有服务地址的路径。

交付前实际打开压缩包核对结构与完整性。源码包若提供，用明确文件白名单或已跟踪源码清单制作，不能直接压缩整个工作区。只有已运行成功的命令和测试才记为通过；实际模型与测试替身证据分别记录，尚未真机验证的范围明确说明。
