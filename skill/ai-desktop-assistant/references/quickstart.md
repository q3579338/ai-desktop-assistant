# 从一张图制作你的桌面助手

## 使用时说什么

在支持 Skill 的 Codex 或 WorkBuddy 中启用 `ai-desktop-assistant`，可以直接说：

> 用这张角色图做一个叫“小禾”的 AI桌面助手，性格温柔但有自己的判断。保持原图，接本机已有模型，记忆与其他角色分开，制作后在后台验证并给我角色包。

需要本地重绘时明确补上“先用本地生图模型重绘”。普通图片导入不需要生图模型；没有指定时不强制改画，也不会将本机连接换成云服务。

已安装 1.10.0 或更新版本时，也可直接使用程序里的“角色 → 从图片创建”，按 [图形制作向导](image-workshop.md) 选图、处理并确认。该界面用随包工具和程序自己的角色库，不要求另找源码；下面的命令行路线仍需要完整源码与相应 Python 依赖。

## 技能包负责的完整流程

当前统一制作 2D 插画助手。先确认静态形象，再按需制作小幅二维动作；聊天、记忆和工作提醒继续兼容。已有预渲染图片或动画仍可导入使用，不因制作路线改变而删除；不再提供实时三维模型制作。

1. **检查已有环境和原图**：确认实际程序、模型与服务；查看图片，保留原始文件。只探测不代表已经生成或推理。
2. **制作形象**：直接使用常见格式图片（内部标准化为PNG），或按用户选择调用已准备好的本地 ComfyUI 重绘。结果要检查完整性、角色一致性、透明背景；单张重绘不等于动画。
3. **形成角色包**：名字、人设和说话风格与形象一起打包，调用应用实际角色库重新导入验证。生成独立制作报告和使用说明。
4. **连接聊天与记忆**：在程序里选择该角色和已确认的本机聊天模型，测试真实回复、重新加载记忆和角色隔离。保存后才更改正式连接，不能拿测试资料覆盖真实档案。
5. **检查并交付**：后台检查尺寸、按钮、任务提醒优先和取消恢复，交付程序、角色包、Skill 与准确的能力说明。

Skill 组织这些步骤；独立桌面程序负责显示和互动；本机模型负责推理。模型权重和 Python 推理环境体积较大，独立准备，不塞进轻量 Skill 包。已有环境可复用，换电脑需重新检查。

## 换一台电脑需要哪些文件

下面的 `<skill>`、`<助手源码目录>`、`<工作区>` 和模型路径均由这台电脑的实际位置替换，可以放在不同目录。`<工作区>` 只是原制作机器的记录，不是运行条件。先把压缩包解压，不能在 ZIP 内直接运行脚本。

| 内容 | 用途与必需范围 |
| --- | --- |
| 完整 `ai-desktop-assistant/` 文件夹 | 包含 SKILL.md、agents、references、scripts、tests；脚本之间有相互导入，只复制 create_assistant.py 不够。按所用宿主的 Skill 安装方式放置，宿主能发现 Skill 不等于依赖已安装。 |
| 与程序版本匹配的助手源码 | 统一入口的 `--app-source` 必填，目录内至少能找到 main.py、starpet/rolepacks.py 及其同包模块；使用完整、可信的源码包。EXE 所在目录不能代替源码目录。源码只用于调用既有角色验证器，不应来自角色包指定的脚本。 |
| 已准备好的 Python 与依赖 | 探测和固定生图客户端用标准库；角色打包需要该 Python 可用的 PySide6，或源码的兼容 `.vendor`。去背景另需 NumPy、Pillow、ONNX Runtime。Qwen 聊天另需对应 PyTorch/Transformers 等环境，见各专项说明。脚本不会自动安装这些依赖。 |
| 完整桌面程序目录 | 用于实际显示、导入角色、聊天与互动；Windows 的 StarPet.exe 和 `_internal` 一起保留。完成角色包不等于已经构建、安装或启动程序。 |
| 用户明确选择的本机模型与服务 | 静态 PNG 打包不需要模型；重绘需要可信的本机 ComfyUI 与兼容 checkpoint，去背景需要固定摘要的 U2NetP，聊天需要本机聊天模型。三者分别检查，不必为了换图准备全部模型。 |

开始前确认 Python 版本满足所选依赖，输入图片可读，制作目录和系统临时目录可写，并有实际需要的内存、显存与磁盘空间。不要把虚拟环境、GPU 依赖或本机 runtime 安装说明原样复制到另一台电脑后就认定可用；按 [本机生图](local-image.md) 与 [本机聊天](local-chat.md) 的前提重新核对来源、摘要、许可和兼容性。已有模型的来源或内容无法核实时，先完成不依赖推理的步骤，报告缺项，不自动下载或换云服务。

统一入口会在系统临时目录建立独立、短路径的打包目录并清理；如果默认临时目录不可写，可在启动该 Python 进程前把 `TEMP`、`TMP` 设为本次工作区内已存在的可写短路径。不要指向正式状态目录或只读的 Skill 安装目录，也无需修改系统级环境变量。

**调用生图前先验证角色打包依赖**，避免图已经生成才发现缺少 PySide6。下面只读原图、在隔离临时角色库中验证并生成新的 ZIP，不调用模型、不启用角色；输出文件名应未被占用：

```powershell
python -B "<skill>/scripts/build_rolepack.py" --app-source "<助手源码目录>" --image "<角色.png>" --name "小禾" --personality gentle --output "<工作区>/首次检查.rolepack.zip"
```

这一步失败时先解决它报告的源码、依赖或图片问题。成功后再选择下面的重绘流程；只需要原图角色包时，这份经过重新导入的 ZIP 本身即可使用。

## 统一制作入口

已有 PNG、JPG/JPEG、WebP、BMP、TIF/TIFF 或 GIF，直接制作（动态/多页只取第一帧）：

```powershell
python "<skill>/scripts/create_assistant.py" --app-source "<助手源码目录>" --image "<角色.png>" --name "小禾" --persona "温柔、自然，有自己的判断，认真回答用户的问题。" --personality gentle --output-dir "<工作区>/我的助手"
```

明确要求本地重绘、且已有运行中的 ComfyUI 与完整 checkpoint 时：

```powershell
python "<skill>/scripts/create_assistant.py" --app-source "<助手源码目录>" --image "<角色.png>" --name "小禾" --personality gentle --output-dir "<工作区>/我的助手" --generate --comfy-url "http://127.0.0.1:8188" --checkpoint "<实际列出的模型名.safetensors>" --prompt "保持角色身份和服装，完整轮廓，统一插画风格"
```

输入要求按所选步骤分别检查：普通角色打包支持上述常见格式，非PNG先保存原始文件并标准化，JPEG校正方向、透明度保留；动态/多页只取第一帧。最终PNG重绘额外要求 8 位、非交错 RGB/RGBA PNG，单边 256～1024 像素且为 8 的倍数、文件不超过 16 MiB；去背景要求见 [本机生图引擎](local-image.md)。不要把重绘尺寸限制误当成所有静态角色的限制。需要适配输入时另存副本，保留原图与摘要。

每次在 `--output-dir` 下新建一个 `assistant-<随机值>` 目录，不覆盖已有制作成果。使用标准输出或 result.json 中的 `output_dir` 找到本次目录；成功标志是 `status="completed"`、`created=true` 和角色包 `import_verified=true`，并核对角色 ZIP 确实存在、摘要相符。退出码为 0 表示本次入口成功，非 0 需读取阶段报告；如果连输出目录都无法建立，可能只有终端 JSON，没有落盘报告。出图阶段失败就停止后续打包，不会自动恢复或重复提交。

成功报告意味着角色包构建和重新导入通过，不代表已自动启用、连接模型或完成用户桌面验收。去背景报告的 `needs_visual_review=true` 仍要求检查实际边缘。

需要透明背景时，在上述命令中显式增加：

```powershell
--remove-background --background-model "<本机已校验的u2netp.onnx>"
```

此选项对原图或重绘结果进行本机去背景，再将透明 PNG 打进角色包；原图和重绘图都保留。它不下载模型，不把颜色相近的部分简单全部删除。小模型可能漏掉胡须、头发或衣边，仍须检查实际透明图与桌面预览。仅有 alpha 通道不代表边缘合格。

在 AI桌面助手的“角色”页导入生成的角色包，预览后使用。连接方式、账号资料和个人记忆不随角色包传递；新角色有独立记忆。需要后台聊天验证时使用新的测试目录和虚构记忆，不能往用户真实聊天里塞测试句。

## 中断或失败后怎样继续

保留本次 `assistant-...` 中的 result.json、README.md、source.<原始后缀>、内部 source.png 以及已有的 generation/job.json、portrait.png、cutout.png 和对应处理报告；文件按实际完成阶段存在，不能要求失败阶段已生成全部文件。原图副本和已完成的结果可用于核对，不因重试删除旧目录。

| 停止位置 | 下一步 |
| --- | --- |
| create_output / validate / copy_source | 检查输出权限、真实源码位置、原图及参数。修改后新开一次制作；尚无生图提交时不涉及重复推理。 |
| generate 且有已确认 prompt_id | 先看本次 job.json 的状态。queued、timed_out、client_stopped 或 `server_may_continue=true` 可能仍在服务中执行；只按本次已确认任务编号检查，不浏览其它任务或调用全局中断。 |
| submission_unknown / unknown | 受理情况不确定，requested_prompt_id 不能当作已确认编号。保留记录并检查本次服务状态；不能因为没收到响应就自动重新提交，也不能宣称已经取消。 |
| remove_background | 先保留已生成的 portrait.png，检查固定模型摘要、依赖与图片。确有需要时用独立去背景脚本处理到新的输出路径，不重跑已经成功的生图步骤。 |
| package / verify | 检查可信源码、PySide6、临时目录、图片及摘要。可对已经确认完成的图片单独调用 build_rolepack.py，输出新 ZIP；原图在制作期间发生变化时先查明原因，不跳过核对。 |
| report | 说明或结果文件写入失败，本次不能标完成。先处理磁盘与权限问题；核对已有图片和包，必要时只重做打包检查，不以“ZIP 已存在”替代完整验收。 |

当前入口**没有 `--resume` 参数**。把带 `--generate` 的整条命令再执行一次会创建新目录并再次请求生图；它不是从上次停止处继续。只有明确确认旧任务不再执行且需要新的生成时，才开始新的生成请求。技术错误的汇总会隐藏底层库输出和配置；例如 package 阶段的笼统错误，可在新输出路径运行上面的独立打包命令得到具体的源码、图片或 PySide6 提示，不能向用户索取认证文件来诊断。

从成功的中间图片恢复打包时，保留整套来源记录，并向 `build_rolepack.py` 传正确的 `--source-kind`：原图为 `user_image`，本机重绘为 `local_img2img`，原图去背景为 `local_background_removal`，重绘后去背景为 `local_img2img_background_removal`。它记录的是包内最终图片的摘要；最初原图与生成任务链仍由本次制作报告保存。不要把本机生成的中间图再按默认“用户原图”来源交付。

## 本机模型分别负责什么

| 部分 | 当前路径 | 注意事项 |
| --- | --- | --- |
| 文字聊天与陪伴 | Ollama 兼容本机接口，或配套 Qwen3-4B 服务 | 先检测实际模型；只用已有模型，不偷偷下载或转发到云端 |
| 从图重绘静态形象 | ComfyUI 固定核心八节点流程 | 需兼容完整 checkpoint；不保证透明边缘或身份完全一致 |
| 形象与桌面互动 | AI桌面助手原生程序 | 静态图可点击拖动；连续动作需要真实动画素材 |
| 长期记忆 | 应用本机文件、每个角色独立 | 可查看、编辑、忘记；不是模型自动改写用户事实 |
| 真实工作完成提醒 | Codex 日志适配与 WorkBuddy Hook | 与聊天登录分开，工具结束不能冒充整轮完成 |

Qwen 服务的启动与程序按钮见 [本机聊天引擎](local-chat.md)。图片流程及能力边界见 [角色制作流程](character-pipeline.md)。验收与发布要求见 [验收与交付](verification-delivery.md)。

本机生图说明中的 `server_control.py` 管理的是原制作机器已经准备的那套 ComfyUI 安装，**不在轻量 Skill 包中，也不是换机启动命令**。其它电脑已有可信 ComfyUI 时直接填它的实际回环地址；服务尚未准备好时按专项说明准备并重新验证。Skill 不会替用户启动未知服务或静默引入模型。

## 技能修订1.13.1的常见格式与摘要

命令行新增常见图片格式支持，使用助手1.12或更新源码中的有界解码器；配对工具仍要求1.13或更新。角色包里的图片始终是PNG。完整制作目录保留原始字节副本，单独打包工具保持外部原图不变。`build_rolepack`的`source_sha256`是包内标准化图片摘要，`original_sha256`是用户原始文件摘要；非PNG的来源说明记录两者。生成请求校验使用内部PNG摘要，不能错误地拿原始JPEG摘要核对。

Python需能导入匹配的PySide6，紧凑透明WebP另需Pillow回退解码；不下载依赖、不自动缩放至模型尺寸。静态转换、HTTP替身测试与真实模型推理分开报告。
